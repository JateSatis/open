# Проверка на устройстве

Два инструмента. Оба сами ставят то, чего не хватает (scrcpy, Maestro), и не зависают:
каждый вызов adb ограничен таймаутом.

- `node scripts/device.mjs <команда>` — окружение и ручная разведка: поднять, посмотреть
  экран, ткнуть, дождаться, снять кадр, записать анимацию. `help` — все команды. Зови через
  `node`, не через `npm run device --`: npm добавляет ~0,7 с к каждому вызову.
- `npm run e2e` (`scripts/maestro.mjs`, сценарии в `.maestro/`) — повторяемые сценарии:
  прошли один раз — гоняются при каждой следующей задаче как регресс.

## Скорость: главное правило

Время самопроверки уходит не на adb (тап и дамп экрана — ~2,5 с), а на простой: угаданные
`sleep`, циклы опроса, холодный старт окружения посреди задачи, повторные полные прогоны.

- **Никаких `sleep` перед и после действий на экране.** `tap` и `swipe` сами ждут появления
  цели до 10 с. Дождаться результата — `wait <цель>` (или `wait <цель> --gone`): команда
  возвращается сразу, как только экран готов. Свои циклы `for … ui | grep … sleep` не пиши.
- **Цепочка — одной командой через `&&`**, а не отдельным вызовом на каждый шаг:
  `D="node scripts/device.mjs"; $D tap text:Plany && $D tap id:comments-button --n 0 && $D wait id:comments-panel && $D shot panel`.
- **Окружение — один раз, в начале задачи, в фоне** (ниже). Не перезапускай Metro и
  эмулятор «на всякий случай»: холодная сборка бандла — ~4 минуты.
- **`ui` — когда не знаешь, что на экране.** Знаешь цель — сразу `tap`/`wait`.

## Окружение

`node scripts/device.mjs up` — всё недостающее одной командой: эмулятор `open_test`, Metro
(свёрнутым окном), прогрев бандла, `adb reverse`, выравнивание часов эмулятора, Open открыт
на списке чатов. Что уже работает — не трогает: на готовом окружении ~7 с, с нуля — пара
минут. Запускай в фоне (`run_in_background`) в самом начале задачи и читай код, пока оно
поднимается.

- `--second` — ещё и `open_test_2`, для сценариев на двух аккаунтах. Второй эмулятор грузится
  минуты: поднимай, только если вторую роль нельзя сыграть SQL-вызовом от имени пользователя
  (память `test-devices-and-accounts`).
- `-s <serial>` — только это устройство (телефон по USB), эмуляторы не запускаются.
- Что-то сломалось посреди работы — `doctor --fix`: Metro и манифест, порт, часы, Open
  наверху. Белый экран — память `white-screen-stuck-metro`.
- Кто под каким аккаунтом — память `test-devices-and-accounts`. Устройств несколько —
  везде `-s <serial>` (для Maestro — `--device <serial>`).

## Экран

- `ui` — компактное дерево: `#testID`, "текст", [подпись], `tap`, `focus`, центр `@x,y`.
- `tap <цель>`: `id:<testID>`, `text:<точный текст>`, `desc:<подпись>`, подстрока, `x,y`.
  Несколько совпадений — скрипт выведет их и попросит `--n`. `--long` — долгое нажатие.
  `text:` ищет по всему экрану: имя чата в шапке открытого чата — тоже совпадение.
- `wait <цель> [--gone] [--timeout сек]` — дождаться появления или исчезновения.
- `swipe <цель> left 300 250` — свайп от центра цели; `swipe x1,y1 x2,y2 ms` — по точкам.
- `text <ascii>` — только латиница (ограничение `adb input`); `key back|enter|del`.
- `shot [имя]` — скриншот, печатает путь к PNG: открой его через Read и посмотри.
- `record <сек> [имя]` + `frames <mp4> [fps]` — анимации и жесты: запись scrcpy и раскладка
  на кадры. Рывок, мигание, промежуточный кадр не того состояния ищи в кадрах, а не на глаз
  по одному скриншоту (подробности — память `screenrecord-blocked-use-scrcpy`).

Каждый жест сначала проверяет, что наверху Open, и отказывается, если нет (выход 3): слепой
тап по рабочему столу realme менял обои. `key back` на корне стека выводит из приложения.
Вернуться к списку чатов из любого места без перезапуска:
`adb -s <serial> shell am start -a android.intent.action.VIEW -d openger://chats`.

Нужного `testID` нет — добавь его в компонент: это дешевле координат и пригодится Maestro.

## Сценарии Maestro

`.maestro/*.yaml` — сценарии, `.maestro/subflows/open-app.yaml` — общий вход: ссылкой
возвращает уже загруженное приложение к списку чатов (секунды) и перезапускает его, только
если оно не загружено. Ждёт строк списка (`chat-list-item`), а не заголовка.

- Пока пишешь или чинишь сценарий — гоняй **только его**:
  `node scripts/maestro.mjs --device <serial> test .maestro/<файл>.yaml`. Упал шаг — посмотри
  экран через `device.mjs ui`, а не перезапуском сценария вслепую.
- **Весь набор — один раз, перед сдачей**: `npm run e2e -- --device <эмулятор>` (~3 мин).
  Повторный полный прогон — только если после него менялся код.
- Цели — по `id:` (testID) и точному тексту; координаты не используй.
- Чат по умолчанию — `env: CHAT` в шапке сценария (на эмуляторе с основным аккаунтом —
  «Plany»); на другом аккаунте — `-e CHAT=<имя>`.
- Сценарий оставляет данные как были: отправил тестовое сообщение — удали его в том же
  сценарии (старые сообщения тестовых аккаунтов не трогать). Текст — латиницей с меткой
  времени: `evalScript: ${output.msg = 'maestro-' + Date.now()}`.
- Сценарий проверяет поведение, а не вид: появилось, исчезло, в фокусе. Плавность и вид —
  запись и скриншоты.

Когда писать новый сценарий: фича с понятным путём «открыть → сделать → увидеть результат»,
который легко сломать соседними правками (жесты, шиты, меню, отправка). Сценарий пишется
вместе с фичей и коммитится с ней.

## Чего не делать

- Не запускать сценарии на realme без нужды: это личный телефон человека, Maestro на время
  прогона ставит на него свой драйвер и перезапускает Open. Регресс — на эмуляторе.
- Не менять настройки защиты устройства (Play Protect и т. п.) — только просить человека.
