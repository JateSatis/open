# Проверка на устройстве

Два инструмента. Оба сами ставят то, чего не хватает (scrcpy, Maestro), и не зависают:
каждый вызов adb ограничен таймаутом.

- `npm run device -- <команда>` (`scripts/device.mjs`) — ручная разведка: посмотреть экран,
  ткнуть, снять кадр, записать анимацию. `npm run device -- help` — все команды.
- `npm run e2e` (`scripts/maestro.mjs`, сценарии в `.maestro/`) — повторяемые сценарии:
  прошли один раз — гоняются при каждой следующей задаче как регресс.

## Начало

1. `npm run device -- devices` — что подключено (realme `df79e451`, Samsung, эмуляторы;
   кто под каким аккаунтом — память `test-devices-and-accounts`). Устройств несколько —
   везде `-s <serial>` (для Maestro — `node scripts/maestro.mjs --device <serial> test …`).
2. `npm run device -- doctor -s <serial>` — Metro (статус и манифест), adb reverse, часы,
   приложение наверху. `--fix` пробрасывает порт и открывает dev build. Metro не запущен —
   память `metro-start-detached`; белый экран — `white-screen-stuck-metro`.

## Разведка экрана

- `ui` — компактное дерево: `#testID`, "текст", [подпись], `tap`, `focus`, центр `@x,y`.
  Вместо сырого `uiautomator dump` — в десятки раз короче.
- `tap <цель>`: `id:<testID>`, `text:<точный текст>`, `desc:<подпись>`, подстрока, `x,y`.
  Несколько совпадений — скрипт выведет их и попросит `--n`. `--long` — долгое нажатие.
- `swipe <цель> left 300 250` — свайп от центра цели; `swipe x1,y1 x2,y2 ms` — по точкам.
- `text <ascii>` — только латиница (ограничение `adb input`); `key back|enter|del`.
- `shot [имя]` — скриншот, печатает путь к PNG: открой его через Read и посмотри.
- `record <сек> [имя]` + `frames <mp4> [fps]` — анимации и жесты: запись scrcpy и раскладка
  на кадры. Рывок, мигание, промежуточный кадр не того состояния ищи в кадрах, а не на глаз
  по одному скриншоту (подробности — память `screenrecord-blocked-use-scrcpy`).

Каждый жест сначала проверяет, что наверху Open, и отказывается, если нет (выход 3): слепой
тап по рабочему столу realme менял обои. `key back` на корне стека выводит из приложения.

Нужного `testID` нет — добавь его в компонент: это дешевле координат и пригодится Maestro.

## Сценарии Maestro

`.maestro/*.yaml` — сценарии, `.maestro/subflows/` — общие куски (`open-app.yaml`
перезапускает приложение и ждёт вкладку «Чаты»). Сейчас есть: запуск и вкладки, отправка и
удаление сообщения, свайп ответа, шит комментариев.

- Один сценарий: `node scripts/maestro.mjs --device <serial> test .maestro/<файл>.yaml`;
  все: `npm run e2e -- --device <serial>`. Каждый сценарий ~40–60 с, из них ~30 — запуск.
- Цели — по `id:` (testID) и точному тексту; координаты не используй.
- Чат по умолчанию — `env: CHAT` в шапке сценария (на эмуляторе с основным аккаунтом —
  «Plany»); на другом аккаунте — `-e CHAT=<имя>`.
- Сценарий оставляет данные как были: отправил тестовое сообщение — удали его в том же
  сценарии (старые сообщения тестовых аккаунтов не трогать). Текст — латиницей с меткой
  времени: `evalScript: ${output.msg = 'maestro-' + Date.now()}`.
- Сценарий проверяет поведение, а не вид: появилось, исчезло, в фокусе. Плавность и вид —
  запись и скриншоты.

Когда писать новый сценарий: фича с понятным путём «открыть → сделать → увидеть результат»,
который легко сломать соседними правками (жесты, шиты, меню, отправка). Сценарий пишется
вместе с фичей и коммитится с ней.

## Чего не делать

- Не запускать сценарии на realme без нужды: это личный телефон человека, Maestro на время
  прогона ставит на него свой драйвер и перезапускает Open. Регресс — на эмуляторе.
- Не менять настройки защиты устройства (Play Protect и т. п.) — только просить человека.
