# /implement — выполнить задачу от ветки до сдачи

Задача: $ARGUMENTS

Если аргументов нет — промпт выше в переписке. Он написан навыком `/spec`: в нём решения
человека, где лежит код, пункты и критерии приёмки `К<пункт>.<n>`. Решения человека не
пересматривай. Подсказки — не приказ: нашёл путь лучше — иди им и напиши об этом в отчёте.
Код мог уйти вперёд с момента написания промпта — сверяйся с ним, а не с промптом.

Процесс — раздел 2 CLAUDE.md. Здесь — как именно его проходить.

## 1. Старт

1. `git status` — рабочее дерево чистое, ты на `master`, он свежий. Чужие незакоммиченные
   правки не трогай и не коммить — спроси.
2. Ветка из промпта (`feat/…`, `fix/…`, `chore/…`) от `master`.
3. Прочитай файлы из «Что прочитать». Сверь, что «Сейчас» в пунктах ещё правда.
4. Если в промпте есть «Вопросы, оставленные исполнителю» — задай те, что уже можно, одним
   `AskUserQuestion` (варианты, рекомендуемый первым), и работай над тем, что от них не
   зависит. Новые продуктовые развилки по ходу — так же, по разделу 10 CLAUDE.md.
5. Если есть инструмент списка задач — заведи задачи по блокам из «Порядок работы».

## 2. Работа

- По блокам из промпта. Блок доводится до рабочего состояния на телефоне, потом следующий.
- Коммиты мелкие, Conventional Commits по-русски, как в `git log`. Миграции — отдельными
  коммитами `feat(db): …`.
- Миграция: файл в `supabase/migrations/`, RLS и индексы в той же миграции, применить к облаку
  (память `db-push-pooler-timeout`), перегенерировать `src/api/types.gen.ts`.
- По ходу гоняй дешёвые проверки: `npx tsc --noEmit` и `npx jest --findRelatedTests <файлы>`.
  Полный прогон — в шаге 4.
- Нативный пакет или правка `plugins`/прав в `app.json` → пересборка dev build своими силами
  (память `android-local-native-build`), в отчёте сказать.
- За рамки задачи не выходи. Плохой код рядом — в отчёт, не в рефакторинг.

## 3. Самопроверка на телефоне

Человек промежуточные этапы не проверяет (память `agent-self-verifies-on-device`). Каждый
критерий приёмки ты проверяешь сам, на устройстве:

- запуск: `npm run usb`; Metro — память `metro-start-detached`, белый экран — `white-screen-stuck-metro`;
- каждая команда adb и каждое ожидание — с timeout (`adb-commands-with-timeout`);
- тапы `adb shell input`, координаты из `uiautomator dump`; перед вводом убедись, что Open на
  переднем плане (`realme-input-guard`);
- скриншоты `adb exec-out screencap -p` в scratchpad, смотри их глазами;
- жесты и анимации — запись через scrcpy (`screenrecord-blocked-use-scrcpy`), разбор по кадрам:
  рывки, мигание, промежуточный кадр не того состояния;
- роли: посетитель-посторонний и участник, где это касается доступа; второе устройство и
  аккаунты — `test-devices-and-accounts`; Supabase с телефона — `supabase-blocked-without-vpn`;
- светлая и тёмная тема, если менялся вид.

Не вышло проверить критерий сам (нужен вход под живым аккаунтом, разрешение на устройстве,
второй человек) — помечай его «проверить человеку», не выдавай за проверенный.

## 4. Перед сдачей

1. `npx tsc --noEmit`, `npx eslint .`, `npx jest` — все зелёные. Падение не из-за твоих
   изменений — скажи явно, не чини молча.
2. Тесты на новое: поведение глазами пользователя, границы доступа обязательно (раздел 8
   CLAUDE.md).
3. Независимая проверка: запусти агента `acceptance-verifier` (передай ему ветку и полный
   список критериев приёмки дословно, с номерами) и `/code-review` на ветку. Найденное —
   исправь или обоснуй в отчёте, почему нет. После исправлений — снова шаг 1.
4. Всё закоммичено, `git status` чистый.

## 5. Отчёт человеку

Коротко, по разделу 2 CLAUDE.md, в таком порядке:

1. **Что сделано** — по пунктам промпта, по одной-две строки.
2. **Чек-лист для телефона** — только то, что человеку стоит потрогать руками: критерии,
   помеченные «проверить человеку», и самые важные по ощущению (жесты, анимации). Формат:
   экран → действие → ожидаемый результат, с номером критерия. Остальные критерии — одной
   строкой «проверены агентом на <устройство>: К1.1, К1.2, …».
3. **Ключевые скриншоты** — пути к файлам; если смотреть надо анимацию — к записи.
4. **Решения, которые стоит перепроверить** — из промпта («Что ещё отметить в отчёте») и твои.
5. **Что за доступом человека** — дашборд, секреты, сборка под iOS.
6. **Замечено за рамками задачи.**

Затем жди. Правки по замечаниям — в той же ветке, снова шаги 3–5. Мердж — только после
«мерджи»: `git merge --no-ff` в `master`, удалить ветку.
