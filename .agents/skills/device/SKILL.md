# Проверка на устройстве

Перед работой прочитай `AGENTS.md`: правила Codex, фоновый запуск и путь к памяти.

- `node scripts/device.mjs <команда>` — окружение и ручная разведка. `help` — все команды.
  Зови через `node`, не через `npm run device --`: npm добавляет ~0,7 с к каждому вызову.
- `npm run e2e -- <набор>` (`scripts/maestro.mjs`) — сценарии из `.maestro/` с уборкой,
  чистым стартом, повтором упавшего и журналом `.maestro/stats.json`.

## Где проверять: телефон по умолчанию

Человек подключает свой realme (`df79e451`) и хочет, чтобы проверяли на нём: это в разы
быстрее эмулятора и честнее для видео и жестов.

1. `node scripts/device.mjs up` (в фоне, в начале задачи) сам берёт подключённый телефон.
2. Вышел с кодом 4 «Телефон не подключён» — **спроси человека** через инструмент вопросов Codex (см. `AGENTS.md`):
   «Подключил телефон» (рекомендуется) / «Не могу подключить — используй эмулятор». Подключил
   — снова `up`. Не может — `up --emulator`.
3. Эмулятор — только по этому ответу. Сценарии с видео (метка `video`) на эмуляторе обёртка
   сама пропускает: там видео ненадёжно и на `master`.

На телефоне учитывай: жесты только когда Open наверху (скрипт проверяет сам), Supabase — через
VPN (память `supabase-blocked-without-vpn`), аккаунт — память `test-devices-and-accounts`.

## Застряло — перезапусти всё, не разбирайся

`node scripts/device.mjs reset [-s <serial>]` — полный перезапуск за 1–2 минуты: драйвер
Maestro, Open, Metro, сервер adb, эмулятор холодным стартом без снимка. Это **всегда
быстрее**, чем разбирать, почему зависло.

Сразу `reset`, без диагностики, если:
- белый экран, «There was a problem loading the project», Open висит на загрузке;
- `uiautomator не отдал дерево экрана` не на видео; adb не отвечает;
- Open выпадает на рабочий стол (ANR), эмулятор «тормозит», сценарии падают пачкой;
- что угодно странное в окружении повторилось второй раз.

`up` и обёртка Maestro делают `reset` сами, если Open не дошёл до списка чатов за 90 с. Если
после `reset` то же самое — дело в коде, а не в окружении: теперь разбирайся.

## Скорость

Время уходит не на adb (тап и дамп экрана — ~2,5 с), а на простой.

- **Никаких `sleep`.** `tap` и `swipe` сами ждут цель до 10 с, результат — `wait <цель>` или
  `wait <цель> --gone`: возвращаются, как только экран готов. Свои циклы опроса не пиши.
- **Цепочка — одним shell-вызовом**, с остановкой при ошибке каждого шага.
  В PowerShell после каждого `node scripts/device.mjs …` проверяй
  `if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }`.
- **Окружение — один раз, в фоне, в начале задачи.** Metro и эмулятор «на всякий случай» не
  перезапускай — для этого есть `reset`, когда действительно застряло.
- **`ui` — когда не знаешь, что на экране.** Знаешь цель — сразу `tap`/`wait`.

## Экран

- `ui` — компактное дерево: `#testID`, "текст", [подпись], `tap`, `focus`, центр `@x,y`.
- `tap <цель>`: `id:<testID>`, `text:<точный текст>`, `desc:<подпись>`, подстрока, `x,y`.
  Несколько совпадений — скрипт выведет их и попросит `--n`. `--long` — долгое нажатие.
  `text:` ищет по всему экрану: имя чата в шапке открытого чата — тоже совпадение.
- `wait <цель> [--gone] [--timeout сек]`, `swipe <цель> left 300 250`, `text <ascii>` (только
  латиница), `key back|enter|del`.
- `shot [имя]` — скриншот, путь к PNG: открой через `view_image`. При живом видео дерево экрана не
  отдаётся — смотри скриншотами.
- `record <сек> [имя]` + `frames <mp4> [fps]` — анимации и жесты: запись scrcpy, раскладка
  на кадры (память `screenrecord-blocked-use-scrcpy`).
- К списку чатов из любого места без перезапуска:
  `adb -s <serial> shell am start -a android.intent.action.VIEW -d openger://chats`.

Нужного `testID` нет — добавь его в компонент: это дешевле координат и пригодится Maestro.

## Сценарии Maestro

У каждого сценария в шапке `tags:` — области (`chats`, `comments`, `channels`, `pops`,
`media`, `subscriptions`, `search`), `smoke` у дыма, `video` у тех, где открывается видео.

| Набор | Что идёт | Когда |
|---|---|---|
| `npm run e2e -- <файл.yaml>` | конкретные сценарии | пишешь или чинишь сценарий |
| `npm run e2e -- changed` | дым + области, которые трогает ветка, + изменённые в ветке сценарии | один раз за задачу, в самом конце перед сдачей — не после каждого блока |
| `npm run e2e -- --tags chats,pops` | дым + названные области | ветка трогает общее, а `changed` промахивается |
| `npm run e2e -- full` | все | по просьбе человека или если полный прогон давно не делали (ниже) |

Обёртка перед прогоном снимает драйвер Maestro, убирает тестовый мусор от прерванных
прогонов (`scripts/e2e-reset.sql`), перезапускает Open с нуля; упавший сценарий повторяет один
раз с чистого старта. Итог по сценарию: **ок**, **нестабильно** (прошёл со второго раза — не
блокирует сдачу, но в отчёт), **упал** (упал оба раза — регресс, чинить код, а не сценарий;
если поведение изменилось намеренно — поправь сценарий и скажи в отчёте). `--no-reset` —
без подготовки, `--no-retry` — без повтора.

### Журнал прогонов и полный прогон

`.maestro/stats.json` (не в git, живёт на машине между ветками) пишет сама обёртка: по каждому
сценарию — прогоны, ок / нестабильно / упало, последние 10 итогов, последняя проблема и её
текст, среднее время; и `lastFullRun` — когда был полный прогон и чем кончился.
`npm run e2e -- stats` — сводка, сверху самые проблемные.

- **В начале задачи** посмотри `npm run e2e -- stats`. Полного прогона не было больше 7 дней
  (или ни разу) — спроси человека через инструмент вопросов Codex (см. `AGENTS.md`): «Полный прогон перед сдачей
  (~25 мин на телефоне)» (рекомендуется) / «Только затронутое». Обёртка сама напоминает об
  этом строкой «Полного прогона не было…».
- Сценарий упал — сначала загляни в журнал: если он и раньше бывал нестабильным, это не
  обязательно твой регресс; перегони его отдельно.

### Как писать сценарий

- Цели — по `id:` (testID) и точному тексту; координаты не используй.
- Вход — `runFlow: subflows/open-app.yaml` (ссылкой к списку чатов, перезапуск только если
  Open не загружен). Не забудь `tags:` в шапке.
- Чат по умолчанию — `env: CHAT` в шапке («Plany»); на другом аккаунте — `-e CHAT=<имя>`.
- Сценарий убирает за собой в том же прогоне; тестовые тексты — латиницей с префиксом
  `maestro-` и меткой времени (`evalScript: ${output.msg = 'maestro-' + Date.now()}`): по
  префиксу их находит уборка. Новый вид мусора (подписка, закреп, реакция в другом месте) —
  допиши его уборку в `scripts/e2e-reset.sql`.
- Сценарий проверяет поведение (появилось, исчезло, в фокусе), а не вид. Плавность и вид —
  запись и скриншоты.
- Писать его стоит для фичи с понятным путём «открыть → сделать → увидеть», который легко
  сломать соседними правками (жесты, шиты, меню, отправка), — вместе с фичей, в том же коммите.

## Чего не делать

- Не менять настройки защиты устройства (Play Protect и т. п.) — только просить человека.
- Не трогать старые сообщения тестовых аккаунтов и личные фото в галерее
  (`test-devices-and-accounts`).
