## Как расширять поиск

1. Прочитай точку входа и нужный обработчик/хук. Ищи символ через `rg -n 'имя' <область>`;
   сначала имена файлов (`rg --files <область>`), затем нужные фрагменты, без дампа всего дерева.
2. Иди по фактической связи: маршрут → экран → хук/состояние → API → RPC/представление.
   Для визуальной правки путь часто заканчивается раньше БД. Обратные вызовы ищи через
   `rg -l 'имяСимвола' src modules`; это поиск кандидатов, а не полный граф зависимостей.
3. При смене прав или данных открой [бэкенд](map/data.md), при общей инфраструктуре —
   [архитектуру](map/architecture.md). Остальные карточки заранее не загружай.
4. Передай исполнителю найденный путь и проверенные факты по [spec](../.agents/skills/spec/SKILL.md),
   а не весь прочитанный контекст. Нет совпадения — ищи в коде, не подгоняй задачу под карту.

## Нужны правила

Открывай раздел по причине изменения, а не по общему слову «медиа» или «бэкенд» в задаче.
Команда `node .agents/scripts/read-doc.mjs "путь#раздел"` выводит только этот раздел;
без якоря — оглавление. Если нужной темы здесь нет, найди её в оглавлении справочника.

## Источники и поддержка

Правила процесса — [AGENTS](../AGENTS.md); назначение навыков и адаптеров — там же.
Справочники ниже хранят подробные правила в одном месте; карточки дают пути и условия их чтения.
Карта не подтверждает состояние установленной сборки/сервера.
`src/api/feed.ts` содержит неготовые методы; наличие файла/типа не означает реализованную фичу.

При смене точки входа, API, потока данных или статуса фичи обнови только затронутую строку/карточку
в той же задаче; косметическая правка кода не требует обновления карты. Не копируй сюда версии
пакетов, всю схему или историю инцидентов. Новая область — новая строка; карточка нужна, когда
маршрут регулярно приходится выяснять заново. Проверка ссылок и покрытия областей:
`node .agents/scripts/check-instructions.mjs`. Она не проверяет смысл описаний — сверяй его по диффу.
