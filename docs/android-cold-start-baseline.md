19 ноября 2026 года, realme 12 Pro+ 5G. В каждой ячейке с прогонами порядок хронологический внутри сценария. Все интервалы указаны в миллисекундах от первого видимого кадра нажатия по иконке. Целевая строка списка — **Scroll benchmark chat**. Две границы размечались отдельно.

Во всех девяти запусках с сессией строка уже была видна в первом различимом кадре «Чатов». В первом онлайн-прогоне на кадре № 53 список виден, на № 54 снова видна заставка, затем список проявляется окончательно. По определению первого кадра засчитан № 53. Кадры пронумерованы с нуля.

## Устройство, сборка и данные

- realme RMX3840, серийный номер `df79e451`, Android 16, `RMX3840_16.0.5.1300(EX01)`. Дисплей 1080 × 2412, в контрольном чтении 60 Гц. USB подключён, заряд 49 %, температура батареи при стартах 32,6–34,8 °C. Владелец использовал тёмную тему, чистый гостевой профиль — светлую.
- Коммит `ee123eb6e97d904847efa7a2ba1561adda7c8f6f`, ветка `chore/cold-start-baseline`. Локальный `assembleRelease` для `arm64-v8a`, пакет `com.openger.app`, версия 1.0.0 (1). Флаг `DEBUGGABLE` у установленного APK отсутствовал. SHA-256 установленного APK совпал с артефактом сборки: `3cc313c8658a85f59d6714fb7b4e48a98388dc36166aa53b66fe922b0df7fcd3`.
- Expo runtime 1.0.0, встроенное обновление `4830b1aa-27ac-4598-b571-493171b3bb8f`. В профиле с сессией его счётчик успешных запусков составил 5 после разведочного запуска, трёх зачётных с истёкшим токеном и подготовки онлайн. После оставшихся шести запусков — 11. Счётчик прежнего обновления остался 184. Каждый чистый запуск начался с пустых данных приложения, до первого открытия в профиле загруженных обновлений не было.
- Онлайн использовалась активная сеть Wi-Fi. Офлайн до открытия включался авиарежим, Wi-Fi отключался отдельно. Перед каждым нажатием проверялось отсутствие активной сети по умолчанию. Сессия и дисковый кеш в основном профиле сохранялись между прогонами. Системные файловые кеши и состояние ART между запусками сохранялись, телефон не перезагружался.
- Сначала снята серия с уже истёкшим токеном. Его `expires_at` соответствовал **17 ноября, 11:52:25 МСК**. Три прогона — 19 ноября, 15:24:19–15:25:45 МСК. В предварительном проходе в сохранённом списке была выбрана контрольная строка. Затем приложение открыли с сетью, чтобы оно штатно обновило сессию. У того же аккаунта подтверждена отметка известной даты рождения. Новое время истечения — **19 ноября, 16:27:15 МСК**. Все шесть запусков с действительным токеном прошли между 15:28:16 и 15:29:54 МСК. Значение `expires_at` сверено до и после этих серий. Диагностика выполнялась при остановленном приложении через временную установку исходного отладочного APK той же подписи поверх release с сохранением данных. Значения токенов не сохранялись в отчёт или артефакты.

## Как повторить замер

1. Использовать тот же realme, проверить SHA-256 фактически установленного release, runtime и ID запущенного обновления. Для сценария без сессии создать гостя, установить пакет для гостя и перед каждым повтором заново установить его **только для этого гостя** без сохранения данных. Во время замера использовались первый запуск у нового гостя и два цикла `pm uninstall --user <guest> com.openger.app` / `cmd package install-existing --user <guest> com.openger.app`.
2. Для остальных сценариев открыть список с контрольной строкой у аккаунта с указанной датой рождения. Заранее сверить `expires_at` с часами телефона. Для истёкшего токена оставить процесс остановленным, отключить сеть до открытия. В этом замере токен истёк естественно. Для действительного токена оставить достаточный запас срока на обе серии.
3. Перед каждым повтором выполнить `am force-stop --user <user> com.openger.app`, проверить пустой ответ `pidof com.openger.app` и открыть страницу лаунчера с иконкой Open. Включить запись до нажатия. Использовался scrcpy 3.1, H.264, 720 × 1600, максимум 60 кадров/с, 8 Мбит/с, без звука и предпросмотра. Все запуски сделаны одинаковым неподвижным касанием по центру иконки длительностью 100 мс через `input swipe x y x y 100`. В основном профиле использовалась иконка из меню приложений, в гостевом — с рабочего стола.
4. По исходному MP4 взять PTS первого кадра потемнения нажатой иконки за **T0**. Обе метрики равны разности PTS целевого кадра и T0. Для входа искать надпись Open и элементы формы. Для «Чатов» учитывать уже видимую вкладку, в том числе с индикатором. Для строки искать её название. При плавном уходе заставки брать первый различимый рисунок интерфейса, даже если логотип ещё виден. В приложенном скрипте порог для подбора кадра составляет 1 % контраста шаблона, соседние кадры проверены визуально. Для независимого разбора использовать `ffprobe -select_streams v:0 -show_frames` и `best_effort_timestamp_time`.
5. У меток в этих записях расстояние от предыдущего кадра составляет 14–18 мс. Консервативная дискретность разности двух визуальных границ — около 36 мс. Нули времени относятся к видимой реакции лаунчера на нажатие. Задержка между вводом и этой реакцией отдельно не измерялась. При повторе сохранить тот же способ ввода и захвата. Рассчитать медиану трёх разностей и диапазон от минимальной до максимальной.
