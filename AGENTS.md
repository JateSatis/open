## Рабочий цикл

- Общайся по-русски. Человек ставит продуктовые задачи и принимает результат на телефоне.
- `$spec` — изучить задачу, выяснить продуктовые развилки и выдать ТЗ одним блоком в чате.
- `$implement` — выполнить ТЗ, проверить, отдать на приёмку. Старый промпт со строкой
  «Задача для /implement» тоже запускает этот навык. `/spec`, `/implement`, `/device`
  в старых материалах означают соответствующие навыки Codex.
- Навыки: `.agents/skills/{spec,implement,device}/SKILL.md`. Загружай нужный перед использованием.
- Новая задача — ветка от `master`. Продолжение начатой — в текущей ветке после изучения
  `git status`, диффа и истории. Не сбрасывай и не коммить посторонние правки.
  Спрашивай только при реальном пересечении работ.
- Одна реализация за раз, без параллельных рабочих веток и worktree. Навык может поручить
  помощнику исследование или независимое ревью без изменения файлов.
- Мердж — только после согласия человека после проверки; push — только по его просьбе.
- Для изменения только инструкций/навыков проверяй формат, ссылки и дифф. Сборка,
  запуск приложения и полный набор тестов нужны при изменении поведения приложения.

## Инструменты Codex

- Вопросы: доступный инструмент Codex (`request_user_input_async`; `request_user_input` —
  только в поддерживаемом режиме), иначе вопрос в чате. Короткие варианты, рекомендуемый
  первым. Пока ждёшь, делай независимую работу. Отсутствие ответа не означает согласие.
- Фоновые команды: shell-сессия (`exec_command`, затем `write_stdin`), проверяй код выхода.
  Самостоятельно запускаемые фоновые процессы Windows через `Start-Process` — с
  `-WindowStyle Hidden`. Разрешения определяются средой Codex.
- Bash-примеры адаптируй под активную оболочку. В Windows PowerShell после каждого шага
  цепочки проверяй `$LASTEXITCODE`; `&&` поддерживается не везде.
- Скриншоты открывай через `view_image`, а не текстовым чтением.
- `.claude/settings.json` — разрешения и плагины Claude. Они не переносятся в Codex
  автоматически; не отключай sandbox ради совместимости.
